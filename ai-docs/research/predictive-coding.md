# Predictive coding

Research note for somnus. Covers Friston's free energy principle and predictive processing as a computational framework, and evaluates whether and how to adopt it. All numbers are **engineering estimates**.

CLAUDE.md principle: "Every biological appeal in a design must also have an engineering justification; if the engineering doesn't stand on its own, the biology is decoration." This note applies that test to predictive coding.

---

## What predictive coding claims

The **free energy principle** (Friston, 2005–present) proposes that biological brains minimize "variational free energy" — a bound on the surprise of sensory observations given an internal generative model. In the predictive coding formulation:

- Every layer maintains a **prediction** of the layer below's activity, generated by a top-down model.
- Every layer computes a **prediction error** = observed activity − prediction.
- Prediction errors propagate upward; predictions propagate downward.
- Learning updates the top-down model to reduce prediction errors.
- Perception = inference = minimizing prediction error = updating the model's beliefs.

This is a **hierarchical Bayesian inference scheme** implemented as a recurrent computation across layers.

### Relationship to standard deep learning

Standard backpropagation is not predictive coding, but the two are related:
- In a linear predictive coding network, the weight update rule at each layer is local (only needs activity and prediction error at that layer) — no backpropagation through the full network required.
- Non-linear predictive coding (PC-Net, Millidge et al., 2022) can approximate backpropagation in feedforward networks.
- The inference phase (settling prediction errors) adds iterations of forward-backward passes per input — analogous to running an optimization loop before committing to a representation.

## Engineering tradeoffs

### What predictive coding buys

| Benefit | Engineering mechanism | Applicable to somnus? |
|---------|----------------------|-------------------|
| Bidirectional information flow | Top-down predictions + bottom-up errors | Yes — directly maps to binding area ↔ regions |
| Local learning rules | Each layer updates from local error signal | Partially — useful for sleep-cycle updates without full backprop |
| Robustness to missing data | Top-down prediction fills in absent modalities | Yes — handles missing audio/video gracefully |
| Surprise as a learning signal | Prediction error = what's worth learning | Yes — directly useful as replay priority and growth trigger |
| Online inference | Model adapts its belief per input via settling | Maybe — adds latency |

**The most directly useful part for somnus is not the full FEP framework but a specific piece:** prediction error as a signal. Reconstruction error from a SAE (see `sparse-coding.md`) is a form of prediction error — the SAE's decoder predicts the input, and the error drives both learning and growth triggers. somnus already uses this idea without needing to adopt the full PC formalism.

### What predictive coding costs

**Per-input inference iterations (settling):**
- Standard feedforward: 1 forward pass. Done.
- Predictive coding: for each input, iterate the prediction error update rule until it converges — typically 5–20 steps.
- Cost: ~5–20× the feedforward compute per input.
- For a regional concept area with d=384 input, 500 units: one settling step ≈ one forward+backward pass ≈ ~1 ms on GPU. 10 steps = ~10 ms per episode.
- At 25 fps video + continuous audio: ~250 ms of settling per second of experience — faster than real-time at 25 fps, but the margin is narrow.

**Additional parameters (bidirectional weights):**
- Each layer needs both feed-forward (bottom-up) and feedback (top-down) weights.
- Doubles the parameter count of each region. For 384×500: 2 × (384×500×4 bytes) = 1.5 MB per region. Still negligible.
- Does require careful initialization to avoid instability (the feedback weights must not cause runaway predictions).

**Complexity:**
- Full predictive coding requires implementing the inference loop (iterative settling), which is structurally different from standard forward-pass + gradient update.
- Neither `candle` nor `burn` has built-in PC support — requires a custom training loop.
- Existing PC implementations (in Python/PyTorch) are available as reference; porting is non-trivial but feasible.

## Partial adoption vs. full adoption

**Full adoption (implement PC throughout all regions):**
- Replace standard feedforward + backprop in regional concept areas with PC settling + local learning rules.
- Gains: local learning, top-down priors, surprise signal.
- Costs: 5–20× inference compute per input; custom training infrastructure; significant implementation complexity.
- **Verdict:** not justified for Phase 1–3. The compute cost during wake is the primary concern on a real-time system.

**Partial adoption (borrow specific mechanisms):**

| PC idea | Adopted as | Where | Phase |
|---------|-----------|-------|-------|
| Prediction error as learning signal | SAE reconstruction error | Regional concept areas | 3 |
| Top-down prior from binding → regions | Gated feedback embedding (see `multimodal-binding.md`) | Binding ↔ regions | 3 |
| Surprise detection | Reconstruction error > threshold → high-salience episode | Episodic memory, replay priority | 3 |
| Generative model per region | SAE decoder | Regional concept areas | 3 |
| Homeostatic adjustment | SHY-inspired weight decay | Sleep cycle | Already in design |

Partial adoption captures most of the engineering value without the inference-iteration overhead. This is the recommended approach.

## Friston's active inference (not for early phases)

The full FEP framework includes **active inference**: the agent takes actions to minimize expected free energy, not just to minimize current prediction error. This covers goal-directed behavior, exploration, and decision-making.

For somnus: this is an eventual Phase 5+ consideration, when an action loop exists. Right now there is no action space, so active inference is irrelevant.

---

## Predictive coding and the sleep cycle

One underexplored connection: the **sleep cycle as free energy minimization at a slower timescale**.

- Wake: fast inference, no weight updates (prediction errors accumulated but not resolved).
- NREM: replay-driven weight updates that reduce the accumulated prediction errors from wake.
- REM: generative replay = the model generating predictions without input, testing its generative model.
- Growth: adding capacity where the model's predictions consistently fail (high free energy, low capacity to reduce it).

This framing is consistent with both the FEP literature and somnus's existing design — without requiring any architectural changes. It is more of a conceptual lens than an engineering commitment.

## Open questions

1. Implement an explicit PC settling loop in Phase 4+ (when compute budget is less constrained), or stay with the partial-adoption approach throughout?
2. Does the local learning rule (no backprop through the full network) actually buy anything for somnus's scale? At <10M params per region, full backprop is not the bottleneck.
3. Is the surprise signal (reconstruction error) from the SAE sufficient for replay prioritization, or does a dedicated prediction-error architecture add measurable value?
